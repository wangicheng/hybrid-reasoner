## 2. 核心評估指標意義說明 (Metrics Explanation)

為了更精確地解讀上述多維度數據表格，以下是本報告中所使用的核心指標定義，以及它們在推薦系統中的實際意義：

- **P@K (Precision at K / 前 K 名精確率)**
  - **定義**：在系統推薦的前 K 本書中，被判定為「相關好書（評分 ≥ 2 分）」的比例。
  - **意義**：衡量系統「找對書」的能力。
- **NDCG (Normalized Discounted Cumulative Gain / 完美排序折扣累積增益)**
  - **定義**：一種嚴格要求「有沒有把最神作排在最前面」的指標。排在第 1 名的 3 分神作能得到極高權重，排後面的權重則被打折。
  - **意義**：衡量系統的「排序精度」。NDCG 越高代表系統極其精準地洞察偏好。
- **pNDCG (Penalized NDCG / 懲罰性 NDCG)**
  - **定義**：在 NDCG 的基礎上，對「踩到使用者地雷（違規）」的書籍進行嚴厲扣分。
  - **意義**：衡量系統在追求推薦品質時，是否因為「語義誘惑」而塞入了違背底線的書籍。
- **Viol@K (違規率) / Clean@K (無違規率)**
  - **定義**：Viol@K 指前 K 名中踩到「硬性規則地雷」的比例。Clean@10 即為前 10 名完全沒有違反的比例 (1 - Viol@10)。
  - **意義**：衡量系統的「規則保真度 (Constraint Fidelity)」。Viol 越低、Clean 越高，代表模型越「聽話」，不會無視使用者的反向標籤要求。
- **Recall@K (召回率)**
  - **意義**：衡量我們到底從茫茫書海中找回了多少比例的「正確書籍」。
- **RBV (Rank-Based Violation) & RC-F1 (Rule-Constraint F1)**
  - **意義**：進階防護欄指標。綜合考量了排序的位置與規則違反的情況。RC-F1 越高，代表系統在「給出好推薦」與「遵守規則」之間取得了越好的雙向平衡。

## 3. 深度剖析：從數據揭露系統現象

這份零死角的數據揭露了三個無法被初步數據看出的深層現象：

### 🎯 現象一：CL40 是「排列精度 (Sorting Precision)」的絕對顛峰
- 觀察 **NDCG@K** 與 **pNDCG@K** 表格，`CL40` 在所有的深度都拿下了最高分（NDCG@1: 97.22%, pNDCG@1: 91.39%）。
- **為什麼 50、75、200 分數反而下降？** 
  這印證了 **LLM Listwise Reranking 的「注意力稀釋 (Attention Dilution)」現象**。把 200 本書丟給模型進行排列時，池子裡混入了大量雜訊。模型在龐大的比較矩陣中迷失了焦點，導致排序出現失誤。

### 🎯 現象二：「語義誘惑」導致規則約束力 (Viol) 持續崩壞
- 觀察 **Viol@10 (前十名違規率)** 與 **Strict-Only Avg**：隨著 CL 從 20 開到 75/200，違規的比例持續上升（從 57.92% 爬升到 62.5%）。
- **原因**：Reranker 很容易被底層池子裡「氛圍極其優美，但踩到了用戶排除標籤」的書強烈吸引。要讓系統完全守規矩，`CL20` 是唯一的王者（無違規率 Clean@10 達 42.08%）。

### 🎯 現象三：CL75 與 CL200 的全線崩潰
- `CL75` 的榜首違規率 (Viol@1) 高達 **58.33%**，代表把 75 本書交給 LLM 重排後，第一名有超過一半的機率踩雷。
- `CL200` 不但違規率沒有改善，連 P@10 (86.67%) 與 mAP@10 (84.4%) 都大幅落後給 CL40。證實了極端候選池在 PermSC 排列法中是完全無效且有害的。

## 4. 最終架構決策結論

綜合這份 100% 公正的嚴峻考驗，給予推薦引擎架構的最終建議如下：

1. **🚀 推薦預設值選定：`CL=40`**
   它不僅達成了 **97.22% 的 NDCG@1** 奇蹟，同時在 pNDCG 與召回率上都取得了最強的平衡。
2. **🛡️ 嚴格模式選定：`CL=20`**
   若需要「嚴格不踩雷模式」，應切換為 CL=20，以換取最低的違規率與最高 42% 的 Clean@10。
3. **⚠️ 絕對避免的雷區：`CL ≥ 75`**
   千萬不要為了迷信「大力出奇蹟」而把 Rerank 池開到 75 或 200。這會消耗高達 10 倍的 LLM API 成本，換來 mAP 下滑、違規率暴增的「三輸」慘況。
