## 1. 實驗設計

### 目的
比較 Gemma 4 在 prompt 中**有/無標籤敘述 (Tag Description)** 對查詢解析和推薦品質的影響。

### 變數設定

| 項目 | Control（無敘述） | Treatment（有敘述） |
|------|-------------------|---------------------|
| Tag List 格式 | 純標籤名稱 (e.g. `戀愛, 後宮, 校園`) | 標籤名稱 + 敘述 (e.g. `戀愛: 以戀愛關係與感情發展為核心的作品。`) |
| Parser 模型 | `gemma-4-31b-it` | `gemma-4-31b-it` |
| Judge 模型 | `gemini-2.5-flash-lite` | `gemini-2.5-flash-lite` |
| 查詢數量 | 20 | 20 |
| Top-K | 10 | 10 |
| 標籤數量 | 60 個 | 60 個（含敘述） |

### 實驗流程
1. 同一查詢分別以 Control 和 Treatment 的 tag list 送入 `HybridEngine.search()`
2. Engine 內部透過 `all_tags_cache` 將 tag list 注入 LLM prompt 的 `AVAILABLE TAGS` 欄位
3. LLM 根據 tag list 進行語意理解 → 標籤投影 → 結構化約束三步解析
4. 搜尋結果由 LLM Judge (`gemini-2.5-flash-lite`) 以 0-3 分評分
5. 同時計算 Tag Recall / Precision / F1 等標籤對齊指標

### 公平性保證
- ✅ **同一模型**：Control 和 Treatment 都使用 `gemma-4-31b-it`
- ✅ **同一評審**：Judge 模型固定為 `gemini-2.5-flash-lite`
- ✅ **同一查詢集**：24 組查詢（完成 20 組），每組都跑 Control + Treatment
- ✅ **唯一變量**：僅 tag list 格式不同（有/無 description）

## 4. 分析與觀察

### 4.1 Treatment 表現較好的案例

Treatment（有標籤敘述）在以下類型的查詢中有**小幅提升**：

- **情感/氛圍類查詢** (q4, q11, q14)：標籤敘述幫助 LLM 更好理解「黑暗」、「青春」、「百合」等標籤的語意邊界
- **多元素混合查詢** (q3, q7, q12, q13)：敘述有助於 LLM 在面對多重需求時做出更精確的標籤選擇
- **冷門/特定需求** (q5, q18)：敘述提供了額外的語意錨點，讓 Recall 略微提升

### 4.2 Control 表現較好的案例

Control（無敘述）在以下案例中**明顯勝出**：

- **q1 (Δ=-0.70)**: Treatment 的 tag recall 從 50% 降至 0%，可能是過長的 tag list 導致 LLM 分心
- **q9 (Δ=-0.90)**: 最大差距，Treatment 的推薦品質大幅下降
- **q19 (Δ=-0.70)**: Treatment 的推薦品質也明顯下降

這些案例表明，標籤敘述有時會導致 **prompt 過長**，使 LLM 在處理時產生「資訊過載」效應。

### 4.3 Tag Precision vs Recall

| 指標 | Control | Treatment | 分析 |
|------|---------|-----------|------|
| Precision | 43.5% | 46.8% (+3.3%) | Treatment 選出的 tag 更精確 |
| Recall | 71.5% | 70.7% (-0.8%) | 兩者 Recall 幾乎相同 |
| F1 | 50.0% | 51.6% (+1.6%) | 整體 F1 略微提升 |

Treatment 在標籤精確度上有小幅提升，說明**敘述確實幫助 LLM 更準確地選擇標籤**，但這個優勢並未轉化為最終推薦品質的提升。

## 5. 結論

### 主要發現

1. **整體效果持平**：加入標籤敘述後，推薦品質沒有顯著變化（Δ = -0.060，可忽略）
2. **標籤精確度微幅提升**：Tag Precision +3.3%，Tag F1 +1.6%，表明敘述有助 LLM 更準確選標籤
3. **存在負面案例**：部分查詢中 Treatment 顯著退步（q1, q9, q19），可能因為 60 個標籤加上敘述使 prompt 過長
4. **按次數計 Treatment 略勝**：10 勝 7 負 3 平，但勝利幅度通常較小（+0.1~+0.3），而失敗幅度較大（-0.7~-0.9）

### 建議

1. **目前不建議在 production 中啟用 tag description**：整體效果不顯著，且存在退步風險
2. **可考慮選擇性注入**：只對歧義性高的標籤（如「歡樂向」、「黑暗」、「龍傲天」等）注入敘述，減少 prompt 長度
3. **可嘗試更精簡的敘述格式**：目前每個敘述約 15-30 字，可嘗試壓縮至 5-10 字的關鍵詞式敘述
4. **可嘗試在 tag projection 階段選擇性注入**：僅在 tag projection pass 中使用敘述，semantic understanding 階段不使用
