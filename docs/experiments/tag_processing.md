# 實驗與方法評估

## 實驗主題：書籍標籤 (Tags) 的處理方式

為了優化檢索與推薦效果，本實驗探討如何處理書籍的標籤資料，目前規劃以下四種方法進行比較：

### 1. LLM 直接生成 + 硬性規則過濾 (Baseline)

- **說明**：LLM 直接生成欲篩選的標籤，再透過硬性規則進行過濾或評分。
- **特點**：為系統目前的基準 (Baseline) 做法。

### 2. 提供完整標籤集給 LLM + 硬性規則過濾

- **說明**：將系統中所有現有的標籤提供給 LLM 作為參考，讓其從中挑選或生成欲篩選的標籤，並同樣使用硬性規則過濾或評分。
- **特點**：確保 LLM 輸出的標籤皆為資料庫中實際存在的標籤，減少幻覺或無效匹配。

### 3. LLM 直接生成 + Embedding 相似度評分

- **說明**：允許 LLM 自由生成理想的標籤，接著透過 Embedding 計算 LLM 生成標籤與實際存在標籤之間的語意相似度，並以此相似度作為評分依據。
- **特點**：保有 LLM 的彈性，即使生成的標籤不完全吻合實際資料，也能透過語意空間找到最相近的對應標籤。

### 4. 標籤融入文本 Embedding (特徵融合)

- **說明**：將書籍的標籤直接與小說簡介合併，共同進行 Embedding 運算。
- **特點**：讓標籤直接影響語意向量提取的結果，從底層表徵改變語意搜尋 (Dense Retrieval) 的匹配邏輯。

### 5. 獨立多向量空間 + 加權融合 (Weighted Additive)

- **說明**：將書籍的「書名與簡介」與「標籤」分別建立獨立的向量空間（`text_semantic` 與 `tag_semantic`）。檢索時對兩個空間獨立進行相似度計算，並透過給定的權重（如 0.7:0.3）進行線性加權融合。
- **特點**：測試標籤在維持線性貢獻下的影響力，觀察權重比例對 NDCG 的靈敏度。

### 6. 獨立多向量空間 + 乘法模型融合 (Multiplicative Fusion)

- **說明**：同樣使用獨立向量空間，但在融合階段改用乘法模型（`總分 = 文本得分 × 標籤得分`）。
- **特點**：在檢索層級保留特徵的獨立性，並透過非線性的乘法模型來強化「雙重匹配」的加成效果，測試標籤與文本內容的加乘關聯性，強調必須兩者皆高度相關才能獲得高分。

## 評分與評估方式 (Evaluation)

本專案全面採用 **LLM-as-a-Judge** 自動化評分機制 (`src/eval/llm_judge.py`)，取代原本的人工評分 UI (`src/eval/annotate_ui.py`)。

- **評分標準 (0-3 分)**：
  - **3 分 (Highly Relevant)**: 完美符合使用者的核心需求與偏好條件。
  - **2 分 (Partially Relevant)**: 符合部分關鍵需求，是合理的推薦，但非最理想。
  - **1 分 (Marginally Relevant)**: 僅有表面或邊緣的關聯，未滿足核心需求。
  - **0 分 (Irrelevant)**: 完全無關，或是書籍資訊缺失 (如書名 Unknown、無簡介)。
- **評估指標 (Metrics)**:
  - 採用 **NDCG@10** (Normalized Discounted Cumulative Gain) 衡量各推薦引擎的排序品質。
  - **強硬條件仲裁 (Strict Filter)**：在計算 NDCG 前，會先透過 `src/eval/metrics.py` 的程式邏輯審查，若發現違反使用者「硬性規則」(如限制字數、特定連載狀態、必須或禁止的標籤等) 的推薦結果，會將其得分強制降為 0，確保指標準確反映真實的推薦限制。
